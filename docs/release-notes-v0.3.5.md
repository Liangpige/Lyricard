# Lyricard v0.3.5 — 微调点得动了，封面不再被冤枉

这一版修三件用户直接能感觉到的事：小窗口关不掉、时间轴微调按了没反应、以及封面被自己的判据误杀（issue #1 的后续）。

## 时间轴微调（歌词页）

三个叠在一起的问题：

- **按钮方向是反的。** 歌词行按 `位置 + 偏移` 挑，偏移越大歌词越早出现；但歌词页把「提前」接成了负值，「延后」接成正号，而卡片右键菜单里是反过来的。同一首歌在两处点会互相抵消。现在四个胶囊与菜单一致。
- **按下去不重画。** 微调原本只写配置、不重算当前行也不解除防抖。一行歌词常常 6–8 秒，±0.1/±0.5 秒跨不过下一个时间戳，所以按下后画面可以完全不动直到下一句。现在立刻重算并允许回退一行（微调是明确指令，不该被防抖顶住）。
- **反馈换了形式。** 不再在卡片上印「提前 0.5s（偏移 +2.5s）」，改为重放一次「切换到下一句」的动效——淡入 + 6px 上滑，和真正换行是同一个函数 `HopLyric()`。

## 歌词时快时慢（卡住后突然连滚）

时钟纠偏原来是**按帧**钳 ±0.04：60 Hz 下等价于每秒额外补 2.4 秒，叠上 `dt` 能跑到约 3.5× 实速；更糟的是当卡片**超前**时净位移为负，位置倒退、画面冻住，等误差缩小再猛地补回来。

现在纠偏按 `dt` 计算，追赶速度封顶 1.3× 实速且**净位移永不为负**；大跳变才 snap（阈值 1.2 s → 0.8 s）。另外新增日志 `line burst 5 changes within 1s`，下次有同样反馈能直接看到现场。

## 封面

- **占位图判据按播放器开关。** 只有酷狗会画「无封面」占位盘（灰「K」标、模糊 CD），只有它走像素判据；网易云等一律直接采用播放器给的图。v0.3.4 在网易云上把「亮、平、细节少」的真实封面误判成占位图（一个 run 里 6 次判定错 4 次），卡片于是一直挂着上一首的封面。
- **坏 JPEG 不再无法解码。** issue #1 里那份 8296 字节的《Dissolve》封面，PIL 能解、WIC 报 `IOException: 无法从流中读取`。逐段排查发现是 **APP1（EXIF）段损坏**：同一份字节剥掉 APP1 后 `decode=ok`（8286 字节）。现在 JPEG 在解码/入库前会剥掉 APP1。
- **坏响应不进缓存。** 入库前做 magic 检查（JPEG/PNG/GIF/BMP/WEBP）；`ApplyArt` 失败时把该 key 从缓存删掉并记 `art fallback dropped (undecodable)`。不会再出现「一份坏响应把这歌锁死到重启」。

## 小窗口关不掉

「选择歌词…」和调色板的关闭按钮原本挂在 `MouseLeftButtonUp` 上，而标题栏在 `MouseLeftButtonDown` 里调 `DragMove()`——它会捕获鼠标直到按键抬起，把 Up 事件吃掉。改成在 `PreviewMouseLeftButtonDown` 里抢先接住并 `e.Handled = true` 再关闭，另加 Esc 关闭。

## 验证

- 微调：`nudge +0.5 offset=2.5` 立即跟出 `line idx=…`，卡片可见一次跳动；「延后 0.5s」方向正确（2.5 → 2.0）。
- 时钟：稳态 `err=0.00`，无 `line burst`。
- 封面：`--cover "Dissolve|Absofacto|Dissolve"` → `8286 bytes decode=ok`；网易云播放时日志不再出现 `art placeholder` 行。
- 小窗：拾取窗、调色板点 X 均从窗口列表消失。

## 已知限制

- 时间轴偏移仍然是**全局一个数**，不是每首歌一个；它补偿的是「这份 lrc + 这个播放器 + 这条出声链路」的合计误差，换设备/换播放器/换蓝牙耳机后建议重新调。
- 同框模式下歌名与艺人底部仍差约 1px（字体下伸所致）。
