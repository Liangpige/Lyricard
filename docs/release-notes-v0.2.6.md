# Lyricard v0.2.6 · 曲末抽搐的真凶找到了

这一版只有一件事是主菜：**歌播完那一刻卡片抖个不停**。修好之后顺手把托盘菜单的两处短板补齐。

## 抽搐的真凶：位置在曲末来回弹

跑完一首歌的最后两秒，Windows 媒体会话的行为是这样的：位置停在 320（总长），标题还没换。旧代码里有两段逻辑互相打架：

```csharp
if (|target - _pos| > 1.2) _pos = target;              // → 320
if (_pos > total - 0.4)  { _pos = 0; _lineIdx = -1; } // → 0
```

每一拍（33 ms）就循环一次：`320 → 显示最后一句 → 0 → 显示"Waiting for music" → 320 → …`

日志里抓到的原文，一秒里十几轮：

```
line idx=35 at=319.66  …
line idx=-1 at=0.00    ♪ Waiting for music
line idx=35 at=320.00  …
line idx=-1 at=0.00    ♪ Waiting for music
```

**改法**：曲末改成一个锁存状态。位置钉在总长、不再参与位置运算；只有真的换歌才解除，或者位置跳回开头并**持续 2.5 秒以上**（有些播放器在边界会先报 0～1 秒，那种"假装跳回开头"不再被当成 seek，因此不会闪一下第一句）。

## 另外两处

- **托盘菜单在卡片隐藏时弹不出来**：菜单原来锚定在卡片窗口上，而卡片在没有播放器时是隐藏的，WPF 的 `PlacementTarget` 必须可见 → 菜单静默失败。现在改成锚定鼠标坐标（带 device→DIP 换算），没有播放器也能右键托盘。
- **自动切歌时标题连闪**（上一版的 400 ms 去抖仍保留）：新标题稳住 400 ms 才采信，换歌期间统一显示「Waiting for music」，一次换歌只发一次取词请求；两个会话抢标题时有 3 秒兜底。
