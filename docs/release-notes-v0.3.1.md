# v0.3.1 — 网易云切歌后封面停在上一首

修一个根因在**取图那一层**的老 bug：换曲之后，圆形封面常常还是上一首的图，并且整首歌都不再更新。

## 为什么会这样

播放器换曲时先更新标题、艺术家，**缩略图要晚一拍**。我们的轮询（200 ms）在标题刚变的那一拍就把缩略图读了下来——那时还是上一首的图——然后把它记成「新曲的封面」，之后再也不读。于是旧图跟着整首歌。

v0.2.5 的「切歌先清空」和 v0.3.0 的「原子替换」都在显示层（`CardWindow`），清掉或替换的都是同一份没更新过的字节，所以两次都没治到根上。

## 改了什么

只动 `src/Smtc.cs`：

- 切歌后不再「读到即信」，而是进入待确认：记住上一首封面的 **FNV-1a 哈希**，只接受与之不同的图；
- 2 秒内没等到不同的图，就接受现状（同一张专辑、封面确实没变的合法情况），之后 30 秒内每 2 秒再慢看一次，迟到的新图仍然能纠正；
- 读缩略图失败不再永久放弃，改退避重试（200/400/600 ms，上限 1 s）；
- 封面身份改用 `Aumid|Title`（不含艺术家）：播放器常常分两拍上报标题和艺术家，把第二拍当新曲会把好图丢掉重读；
- 日志新增四行，以后排查不用靠像素猜：
  `art wait` / `art stale` / `art ok … changed=` / `art none` / `art late`。

显示层的策略没改：确认之前卡片保持上一张封面（约 200 ms），确认后一次性替换——而不是先空一拍再补，避免闪烁。

## 实测（本机，网易云）

```
00:46:59.743  art wait key=cloudmusic.exe|哪里都是你 prev=4105cfb6c762a1c3
00:46:59.746  art stale 2881 bytes (player is still publishing the previous cover)
00:46:59.957  art ok 623 bytes changed=True

00:47:13.666  art wait key=cloudmusic.exe|Letting Go prev=1428617051140000
00:47:13.669  art stale 2349 bytes (player is still publishing the previous cover)
00:47:13.880  art ok 4209 bytes changed=True
```

修前这两次都会把 2881 / 2349 贴上去（上一首的图）；修后丢弃，并在 ~210 ms 后拿到真正的 623 / 4209。连续切歌 10+ 次，每次切歌恰好一条 `art wait`，没有重复重读。

## 已知取舍

- 同专辑连播：最多空等 2 秒才接受（封面本来就没变，观感无差别）；
- 播放器超过 2 秒才发新图：先按当前图接受，随后慢看纠正；
- 依赖哈希判「是不是同一张图」：同一张专辑里两张**完全一样**的封面会被当成未变（这正是期望行为）。


## 滚轮可配置（新增）

卡片上的滚轮以前固定是缩放，`Ctrl+滚轮` 偷偷调透明度——没人猜得到。现在主页「卡片滚轮」可以选三档：

- **缩放卡片**（默认，保持老用户的手感）
- **系统总音量**：每格 2%，用的是系统主音量（等同音量键），静音状态下向上滚会先解除静音
- **无操作**：滚轮在卡片上什么也不做

`Ctrl+滚轮` 的透明度快捷键已删除（透明度仍在菜单的「更透明/更不透明」和外观页里）。触控板的小增量会先累加成一格再动作，不会一划就跳二十档。

限制：调的是系统总音量，不是单个播放器；卡片开了【交互穿透】时滚轮本来就是收不到的。

## 交互穿透多了一档「只留按钮」

以前是非开即关：一开，卡片连暂停都点不了。现在主页和卡片右键菜单都是三档：

- **关闭**：正常交互
- **全部穿透**：和以前一样，整张卡片不接鼠标
- **只留按钮**：卡片照样透传，只有「上一首 / 播放暂停 / 下一首」那排还能点

做法不是把窗口切成几块，而是让光标位置决定窗口透不透：每 33 ms 读一次光标，落在那排按钮上就把 `WS_EX_TRANSPARENT` 摘掉（再补一次 `SWP_FRAMECHANGED` 让系统刷新命中缓存），移开立刻戴回去。

一个必须知道的细节：分层窗口是**按像素**命中的，全透明的像素连点都收不到。所以「只留按钮」模式下，那排按钮会被垫一层 `alpha = 1/255` 的黑色背景 —— 肉眼看不出来，但对命中测试来说是实心的，图标之间的缝隙也能点中。

代价：进入按钮的一瞬间有 ≤33 ms 的延迟（极快的「移入并点击」可能丢一下）；矩形按 3 Hz 缓存，翻标志只在跨过边界时发生。

## 全屏时隐藏（新增，默认关）

主页新增「有窗口全屏时隐藏卡片」，默认**关**。开启后每 ~300 ms 检查一次：前台窗口是否铺满了卡片所在的那块屏幕（留 2 px 容差，覆盖无边框游戏、浏览器 F11、视频全屏），再用系统的 `SHQueryUserNotificationState` 作补充判断，识别独占全屏。连续两次判断一致才动作，所以来回 Alt-Tab 不会让卡片抽搐。

隐藏只是「不上桌面」的又一个理由，和菜单里的隐藏并存：数据照常更新，退出来的时候画面已经是对的；隐藏期间不再每 1.5 秒抢置顶。普通最大化窗口（没盖住任务栏）不算全屏。

诚实说明：这条我只验证了「最大化窗口不会被误判」，真正的全屏收起没能在本机跑通——我合成的全屏窗抢不到前台，日志里 `GetForegroundWindow` 一直返回 Lyricard 主窗口。如果你开了它却没反应，把 `data\amc.log` 里带 `fullscreen` 的行发我。

## 频谱颜色即时生效

以前改「频谱颜色」要点一次断点、甚至重启才看见。原因不在颜色存没存，而是重画那段有个提前返回：只比较了条数/宽/高/条宽，颜色不在判断里，于是几何没变就直接返回，旧画笔留在那儿。现在颜色也参与判断，几何没变就**就地重新上色**（最多 96 个矩形，不重建），日志里能看到 `bars recolour …`。

## 控制台排版

同一分割线内的行，能排两列的都改成两列（外观页最明显：歌名/艺人、歌词/封面大小、频谱长度/最大高度）。配对是在页面成型的最后一步统一做的，碰到标题、分割线、说明文字就断开——所以一对不会跨过分组线。颜色行保持整行，八个色点并排会看不清。

另外把三个字符上限和封面大小归到新的「模板尺寸」一节，四项正好 2×2；画板下面那句说明也从两行压成一行。
